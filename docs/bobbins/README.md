# Bobbins

A bobbin is the plugin for one outside service. It holds what hookspool needs to take that service's webhooks and turn
them into work: how the sender proves itself, what its events group on, and sometimes a processor that asks the service
what changed. Its name is `<vendor>.<product>`: the company that runs the service, then the product or API surface whose webhooks it
receives (`google.gmail`, `atlassian.trello`, `github.repo`; `hookspool.` is reserved for the generic ones shipped with
hookspool). A deployment turns one on with a `[bobbins.<instance>]` table that names it (`bobbin = "google.gmail"`); see
[the configuration reference](../configuration/README.md#bobbinsinstance).

A service with no push of any kind gets a **poll bobbin**. Instead of a source, it has a `poller.py` that the
dispatcher's clock starts every `every_s` seconds. It has no URL and asks the service what changed
([Poll bobbins](writing-a-bobbin.md#poll-bobbins)). A service that can push always gets a webhook bobbin, never a poll.

## The catalogue

Each name links to the bobbin's own README, which lists its settings, secrets, outputs and limits. `SETUP.md` in the
same directory is the step-by-step setup for a person, and `AGENTS.md` is the same procedure for an agent.

The rows are the manifests' own `summary` lines. A pull request that adds a bobbin does not touch this page; the
maintainer regenerates the table when merging it. `hookspool bobbin list` prints the same list from the installed copy,
and `hookspool bobbin show <vendor>.<product>` prints one bobbin's provider pages and settings.
